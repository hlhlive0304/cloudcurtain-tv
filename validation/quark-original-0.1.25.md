# 0.1.25 夸克原片持续读取验收

2026-10-24。Android TV 11 / API 30 / x86 模拟器，版本 0.1.25-preview / versionCode 26。用户已开通夸克超级会员，重新扫码确认了测试环境登录；电视重登曾短暂正常，随后反馈第二集原画仍卡，而官方客户端播放正常。因此没有将重新登录当作完整修复，也没有把旧的非会员限速数据当作当前账号结果。

## 取流与实现

- 本次保留原片选择及原始文件路径。没有发布早先试验的“自动优先在线转码”方案：该方案虽然能播放 1440×810，但比 1920×1080 原文件低，不能作为原画修复。
- 新 `QuarkRangeSource` 只在 QUARK、可信 HTTPS 下载域、原片或自动原片状态下使用；其他网盘、明确的在线转码及外部地址不启用。继续使用原 `Net.client` 的 Cookie、UA、Referer、重定向及账号退出检查，不生成额外权限或改变签名 URL。
- 每段最多 2 MiB，最多三路网络请求预读后续片段，按请求位置依次交付。内存中当前段和后续三段最多约 8 MiB，播放器本身的缓冲上限保持不变。不是下载整部影片后播放，也没有本地或远程代理。
- 检查 HTTP 206、Content-Range 起止位置及总文件长度；拒绝把 HTTP 200 全文件响应、错误偏移、长度变化或截断的段拼入原片。保持原文件所有字节、分辨率、帧率、音轨与字幕。快进和关闭时取消旧请求及后台任务，重开时从新位置读取。
- 并行网络请求的统计计数同步处理。超时提示不再一律说“没出画面”，已经出画后会说明当前正在等待缓冲。

## 当前账号下的观察

重新登录后，《复联4》接口能返回 3840×1608 在线档位，不再只有旧的 480×202。反馈中的第一集原文件为 1,487,017,901 字节，第二集为 1,487,695,757 字节，均为 1920×1080 AVC。

短时 Range 读取曾达到约 5–7 MiB/s，但随后单连接持续读取会明显下降。旧原片读取路径的 120 秒对照中只渲染了一帧，持续等待缓冲；第二集一次 8 MiB 请求也曾用时约 18 秒。第二集三路各 2 MiB 的探测合计 6 MiB / 760 ms，约 8,084 KiB/s。单连接与分段探测并非在同一瞬间进行，服务器速度也有波动，不能据此承诺固定加速倍数；判断修复效果以实际持续出画和播放进度为准。

缓冲状态样本包含启动和快进，不能写成“零缓冲”。两次均保留 `quality=original`、没有切到在线转码，结束时播放器处于 READY、仍在播放；预读约 60–65 秒。渲染计数用于避免把只走音频时钟当成视频成功。测试未覆盖整集，也未连接真实电视，不能保证电视永远不再等待网络。

另用真实遥控器确定键从第一集切到第二集，目标从头播放，仍为 1920×1080 原片并持续前进。百度 12 集前后切换及返回电影墙、SRT 中文显示/快进/关闭后重选完成回归。百度焦点检查首次失败，未修改焦点代码的重跑通过，原始失败记录保留在本机；本次不宣称解决全部遥控器时序问题。

## 其他检查与范围

- 单元 238 项：236 通过、2 项既有跳过，0 失败。新增分段顺序、字节完整性、跨段快进、末段、范围响应拒绝、取消和重开、启用范围检查；lint 0 错误。

- 4K 原片传输可走同一读取路径，但模拟器不具备完整真机 4K 解码环境；本次成功范围是上述 1080p 原片。天翼杜比视界真机限制、阿里原画暂缓状态不变。
