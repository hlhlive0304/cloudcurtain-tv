# 0.1.24 原片恢复与解码选项验收

2026-10-20，Android TV 11 / API 30 / x86 模拟器，保留原网盘账号。版本 0.1.24-preview / versionCode 25。真实雷鸟电视未连接。

## 实现及范围

- 将恢复策略区分为同画质重取、自动兼容和停止。手动原片或明确清晰度的缓冲超时执行一次同画质重取；不再在调用策略后因 `original` 条件跳过实际恢复。解码失败不会擅自改变手动选择的档位，过期地址和自动兼容使用独立、有上限的预算。
- 夸克自动兼容只接受已经授权的高清线路，以宽至少 1280 或高至少 720 判断，允许电影裁切黑边后的宽屏 HD。只返回低清时说明原因、保留当前来源和进度；人工选择仍能使用实际低清档位。自动首次取流失败的回退也遵守此规则。
- 天翼、夸克至少 256 MiB 的网络原片采用较早补充的缓冲储备及 6 秒启动 / 15 秒重新缓冲目标；选轨分配器上限为堆内存的三分之一且不超过 128 MiB，仍受内存阈值约束，不承诺一定缓存到目标秒数。百度已有策略保留。
- 默认自动解码。按文件主动选择 HEVC 基础层时，只转换 Media3 `getAlternativeCodecMimeType` 判定 HEVC 兼容且未加密的 Dolby Vision 轨道；排除 Profile 5、Profile 7、未知编码、普通 AVC / HEVC。保留原参数集、分辨率、帧率、色彩信息及原样本数据，从参数集获取实际 HEVC codec string，不能把 Dolby Vision profile 作为 HEVC profile。
- 基础层模式使用原视频文件，未调用云端转码；不保留完整 Dolby Vision 效果。切换保留位置、倍速和清晰度，可用遥控器切回自动。没有让不具备 4K HEVC 能力的设备获得该能力。
- 播放诊断增加实际解码器、是否显示首帧和基础层应用状态。每次重建播放器清空旧线路的下载统计，避免混用不同线路的速度和字节数。

依据所使用的 [Media3 1.6.1 基础层兼容判定](https://github.com/androidx/media/blob/1.6.1/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/mediacodec/MediaCodecUtil.java) 及 [视频解码器配置](https://github.com/androidx/media/blob/1.6.1/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/video/MediaCodecVideoRenderer.java)；同时检查了本机实际 1.6.1 依赖字节码。没有假定任意 Dolby Vision profile 都可直接交给 HEVC。

## 已验证

- 单元测试 234 项：232 通过、2 项既有跳过、无失败；lint 0 错误 / 58 警告。
- 使用保留账号的一份天翼普通视频，在原片清晰度、30 秒位置注入不返回数据的本机 HTTP 连接，触发超时。实际重新获取原片地址，1080×1920 AVC 出画并持续前进，位置和 `original` 档位保留，只使用一次恢复预算。即使文件已有基础层偏好，普通 AVC 轨道也不转换。
- 夸克实际《复联4》从 52 秒位置以自动原片打开。模拟器不支持其原片，自动兼容请求只有 480×202，显示低清说明并保留原片及位置。遥控器进入清晰度选项，主动选择返回的低清后才切入，480×202 实际出画、时间轴前进。此项证明选择流程，**不是高清播放通过**。
- 天翼实际《复联4》在基础层模式解析出 3840×2020 `video/hevc`；设备仍报告不支持，没有首帧。遥控器选择自动解码后恢复自动模式。此项证明原尺寸、解码选项和恢复选择，**不是该片成功播放**。
- 真实百度 12 集前后切换、首尾边界、保存离开位置、目标从头、字幕状态重置、重新取地址保留剧集目录、返回电影墙的回归通过。
- 百度实际 SRT 加载、中文显示、时间轴、快进、关闭后重选的回归通过。测试期间隔离进度与历史，结束后恢复原始内容。

原片 HTTP / Range 和速度的具体限制见 [2026-10-20 原片排查](quark-original-2026-10-20.md)。网络线路持续低于原片码率时，增加缓冲不能解决连续播放。当前没有可用的夸克高清线路，真实电视的天翼 4K 解码也仍待验证；本版只交付上文已测的优化。
